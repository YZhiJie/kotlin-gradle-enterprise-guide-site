第 1 章 Kotlin 语言基础 ​

本章帮助你建立 Kotlin 的核心语法直觉，尤其是与 Java 思维差异最大的空安全体系与函数式风格，为后续企业级开发打底。

1.0 学习目标 ​

完成本章后，你将能够：

  1. 正确使用 val/var、类型推断与基本类型，写出符合 Kotlin 风格的声明。
  2. 运用空安全（null safety）四大操作符与作用域函数，彻底规避空指针异常（NPE）。
  3. 使用 when 表达式、数据类（data class）、密封类（sealed class）建模业务状态。
  4. 熟练使用集合操作符与序列（Sequence）处理数据，并理解二者的性能差异。
  5. 编写 lambda、高阶函数与扩展函数，形成函数式编程的基本思维方式。

1.2 变量与常量 ​

Kotlin 区分只读变量（val）与可变变量（var），并具备强大的类型推断能力：

kotlin
// Variables.kt —— 变量与常量声明
const val MAX_RETRY = 3                    // 编译期常量，仅允许基本类型/String

fun main() {
    val name: String = "Kotlin"            // val：只读，相当于 Java final
    var count = 0                          // 类型推断为 Int，可重新赋值
    count += 1
    val createdAt = System.currentTimeMillis()  // 运行时赋值也允许，val ≠ 编译期常量

    println("$name, retry=$MAX_RETRY, count=$count, ts=$createdAt")  // 字符串模板
}

  • ✅ 优先使用 val：不可变引用让并发与重构更安全，企业代码中 val 占比通常在 80% 以上。
  • ⚠️ val 只保证引用不变，不保证指向的对象内部不可变（如 val list = mutableListOf<Int>() 仍可增删元素）。
  • ❌ 不要用 var 收集「稍后赋值」的变量，优先考虑 val + 表达式求值或 lateinit/by lazy（见第 2 章）。

1.3 基本类型 ​

Kotlin 中一切皆对象，没有 Java 意义上的原始类型（编译器会在字节码层面自动选择 int/Integer）：

kotlin
// BasicTypes.kt —— 基本类型与显式转换
fun main() {
    val intVal: Int = 42
    val longVal: Long = intVal.toLong()    // ✅ 必须显式转换，不存在隐式拓宽
    val price: Double = 19.99
    val flag: Boolean = true
    val hex = 0xFF_EC_DE_5E                // 支持下划线提升可读性
    val text = """
        |多行字符串
        |保留原始格式
    """.trimMargin()

    println("$longVal $price $flag $hex $text")
}

1.4 空安全体系 ​

空安全是 Kotlin 相对 Java 最大的生产力提升：可空性与非空性编码在类型系统里，由编译器强制检查。

kotlin
// NullSafety.kt —— 空安全四大操作符
data class User(val name: String, val email: String?)

fun main() {
    val user: User? = User("张三", null)

    // 1. 安全调用 ?.：链上任意一环为 null，整体结果为 null
    val emailLen: Int? = user?.email?.length

    // 2. Elvis 操作符 ?:：为 null 时提供默认值
    val displayLen: Int = user?.email?.length ?: 0

    // 3. 非空断言 !!：为 null 时直接抛 NPE（❌ 生产代码慎用）
    // val forced = user!!.name

    // 4. 安全转换 as?：失败返回 null 而非抛异常
    val any: Any = "hello"
    val num: Int? = any as? Int            // num == null

    println("emailLen=$emailLen displayLen=$displayLen num=$num")
}

作用域函数的选择 ​

let/also/run/apply/with 五个作用域函数的区别仅在两点：接收者形式（it 还是 this）与返回值（lambda 结果还是接收者本身）：

kotlin
// ScopeFunctions.kt —— 五个作用域函数对比
data class Config(var host: String = "", var port: Int = 0)

fun main() {
    val nullable: String? = "enterprise"

    nullable?.let { println("let: 非空才执行，长度=${it.length}") }  // it + 返回结果

    val config = Config().apply {          // this + 返回接收者：对象初始化首选
        host = "api.example.com"
        port = 443
    }

    val summary = config.run {             // this + 返回 lambda 结果：计算派生值
        "https://$host:$port"
    }

    config.also { println("also: 副作用日志 -> $it") }               // it + 返回接收者

    val upper = with(config) { host.uppercase() }                    // 非扩展形式，分组操作

    println("$summary $upper")
}

1.5 控制流与 when 表达式 ​

when 是表达式（有返回值），支持类型判断、范围、任意条件，是 Java switch 的全面升级：

kotlin
// WhenDemo.kt —— when 表达式用法
sealed interface Result                    // 密封接口（见 1.6 节）
data class Success(val data: String) : Result
data class Failure(val code: Int, val message: String) : Result

fun describe(input: Any): String = when (input) {
    is Success -> "成功: ${input.data}"                    // 类型匹配 + 智能转换
    is Failure -> when (input.code) {                     // when 可嵌套
        in 400..499 -> "客户端错误: ${input.message}"
        in 500..599 -> "服务端错误: ${input.message}"
        else -> "未知错误码: ${input.code}"
    }
    is String -> "字符串长度 ${input.length}"
    else -> "未识别类型"
}

fun main() {
    println(describe(Success("订单创建完成")))
    println(describe(Failure(404, "资源不存在")))
}

1.6 类、数据类、密封类、接口与对象声明 ​

kotlin
// ClassHierarchy.kt —— Kotlin 类体系一览
interface Payable {                        // 接口可含默认实现
    fun amount(): Long
    fun describe(): String = "应付 ${amount()} 分"
}

sealed class Payment : Payable {           // 密封类：子类必须同包/同模块
    data class WeChat(val orderId: String, val cents: Long) : Payment() {
        override fun amount() = cents
    }
    data class Alipay(val tradeNo: String, val cents: Long) : Payment() {
        override fun amount() = cents
    }
    object FreeOrder : Payment() {         // object：单例，线程安全
        override fun amount() = 0L
    }
}

fun main() {
    val payments: List<Payment> = listOf(
        Payment.WeChat("W2026", 9900),
        Payment.Alipay("A2026", 19900),
        Payment.FreeOrder
    )
    // 数据类自动生成 copy/equals/componentN，sealed + when 穷尽分支
    payments.forEach { p ->
        val channel = when (p) {
            is Payment.WeChat -> "微信(${p.orderId})"
            is Payment.Alipay -> "支付宝(${p.tradeNo})"
            Payment.FreeOrder -> "免单"
        }
        println("$channel -> ${p.describe()}")
    }
    val discounted = Payment.WeChat("W2027", 9900).copy(cents = 1)  // copy 派生新对象
    println(discounted)
}

1.7 集合与序列 ​

kotlin
// Collections.kt —— 集合操作与 Sequence 对比
data class Order(val id: Long, val amount: Long, val paid: Boolean)

fun main() {
    val orders = List(1_000_000) { Order(it.toLong(), it % 100L, it % 2 == 0) }

    // 普通集合：每一步生成中间 List，大数据量下内存开销明显
    val t1 = System.currentTimeMillis()
    val r1 = orders.filter { it.paid }.map { it.amount }.take(5).toList()
    val eager = System.currentTimeMillis() - t1

    // Sequence：惰性求值，无中间集合，元素级流水线
    val t2 = System.currentTimeMillis()
    val r2 = orders.asSequence().filter { it.paid }.map { it.amount }.take(5).toList()
    val lazy = System.currentTimeMillis() - t2

    println("结果相同=${r1 == r2}, eager=${eager}ms, sequence=${lazy}ms")
}

⚠️ Sequence 不是银弹：元素少（<1000）或操作只有一步时，装箱与迭代器开销反而更慢。经验法则：大数据量 + 多步链式操作才上 asSequence()。

常用操作符速查：filter/map/flatMap（变换）、groupBy/associateBy（分组索引）、fold/reduce（聚合）、partition（二分）、sortedBy/distinctBy（排序去重）。

1.8 函数式编程：Lambda 与高阶函数 ​

kotlin
// HigherOrder.kt —— lambda 与高阶函数
fun <T> retry(times: Int, block: (Int) -> T): T {     // 高阶函数：函数作参数
    var lastError: Exception? = null
    repeat(times) { attempt ->
        try {
            return block(attempt)                      // 调用传入的 lambda
        } catch (e: Exception) {
            lastError = e
            println("第 ${attempt + 1} 次失败: ${e.message}")
        }
    }
    throw lastError!!
}

fun main() {
    var flaky = 0
    val result = retry(3) { attempt ->
        flaky++
        if (flaky < 3) throw RuntimeException("网络抖动")
        "第 ${attempt + 1} 次调用成功"
    }
    println(result)

    val square = { x: Int -> x * x }                   // lambda 赋值给变量
    val add: (Int, Int) -> Int = { a, b -> a + b }     // 显式函数类型
    println("${square(6)} ${add(1, 2)}")
}

1.9 扩展函数 ​

扩展函数允许在不继承、不修改源码的前提下为现有类「追加」行为，静态分派（编译期确定），不会产生运行时开销：

kotlin
// Extensions.kt —— 扩展函数与扩展属性
fun String.toSnakeCase(): String =                     // 为 String 添加扩展
    replace(Regex("([a-z])([A-Z])"), "$1_$2").lowercase()

val <T> List<T>.secondOrNull: T?                       // 扩展属性
    get() = if (size >= 2) this[1] else null

fun main() {
    println("createdAt".toSnakeCase())                 // created_at
    println("UserName".toSnakeCase())                  // user_name
    println(listOf(1, 2, 3).secondOrNull)              // 2
    println(listOf(1).secondOrNull)                    // null
}

  • 接收者为 null 时扩展函数依然可被调用（可空接收者），String?.orEmpty() 即官方示例。

工程实践提示 ​

  1. 从 Java 迁移的次序：新模块直接用 Kotlin 写；存量 Java 类用 IDEA 的「Convert Java File to Kotlin File」转换后，重点人工修订 !! 与平台类型（platform type）。
  2. 统一空安全约定：与 Java 互操作时，给 Java 代码加 @NotNull/@Nullable（JetBrains 注解）可让 Kotlin 侧获得精确类型，消除平台类型隐患。
  3. 数据建模规范：API 出入参用 data class，领域状态用 sealed class，避免用 Map<String, Any> 在层与层之间传数据。
  4. 集合默认值：对外暴露的集合参数默认 emptyList() 而非 null，调用方少一层判空。

实践任务 ​

  1. ★ 编写一个 parseAmount(input: String?): Long 函数：输入可空字符串（如 "19.99"），解析为「分」单位的 Long，非法输入返回 0，要求全程不出现 !!。
  2. ★★ 用 sealed interface 建模一个审批状态机（草稿/审批中/已通过/已驳回/已撤销），并用 when 实现 nextActions(status): List<String> 返回每个状态允许的操作，依赖编译器穷尽检查。
  3. ★★ 给定 10 万条订单数据（id、金额、渠道、是否支付），分别用普通集合与 Sequence 完成「已支付订单按渠道分组求金额 Top3」，对比耗时并解释差异。
  4. ★★★ 实现一个通用高阶函数 inline fun <T> measure(name: String, block: () -> T): T，打印任意代码块耗时，并用它包装任务 3 的两次实验。
  5. ★★★ 为 List<Order> 编写扩展函数 toSummary()，返回数据类 Summary(totalCount, paidCount, totalAmount)，要求链式调用风格。

小结与自测 ​

要点回顾：val 优先；空安全由类型系统保证；when 是表达式且对密封类可穷尽；data class/sealed class/object 是建模三件套；Sequence 适合大数据量多步链式操作；扩展函数静态分派。

自测题：

  1. val list = mutableListOf(1, 2) 之后能否执行 list.add(3)？能否执行 list = mutableListOf()？为什么？
  2. a?.b ?: c 与 a!!.b 在 a 为 null 时行为有何不同？
  3. let 与 apply 在接收者和返回值上的区别是什么？各自最典型的使用场景？
  4. 为什么对 sealed class 的 when 建议不写 else 分支？
  5. 什么情况下使用 Sequence 反而比普通集合更慢？
参考答案（点击展开）
  1. 能 add（val 只锁定引用，不锁定对象内容）；不能重新赋值（引用不可变）。
  2. 前者返回 c 的值，后者抛出 NullPointerException。
  3. let 接收者为 it、返回 lambda 结果，适合可空对象安全操作；apply 接收者为 this、返回接收者本身，适合对象初始化配置。
  4. 不写 else 时编译器做穷尽性检查，新增子类会编译报错，强制开发者处理新分支。
  5. 元素数量少或操作只有一步时，Sequence 的迭代器与装箱开销超过其节省的中间集合成本。
