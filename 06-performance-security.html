第 6 章 性能优化与安全 ​

性能决定体验下限，安全决定生死红线。本章横跨 JVM 服务端与 Android 两端，给出可落地的调优手段与防护清单。

6.0 学习目标 ​

完成本章后，你将能够：

  1. 解释 JVM 内存模型，针对服务特征选择 G1/ZGC 并用 JFR 定位性能瓶颈。
  2. 完成 Android 启动优化、用 LeakCanary 排查内存泄漏、执行包体积瘦身。
  3. 编写 ProGuard/R8 keep 规则，平衡混淆强度与功能正确性。
  4. 使用 Android Keystore 管理密钥并实现加解密。
  5. 落地 HTTPS、证书固定（Certificate Pinning），并对照 OWASP Mobile Top 10 逐项防护。
  6. 在服务端落地接口级认证授权、密钥轮换、传输/存储边界，并对照 OWASP API Security Top 10 自检。
  7. 把 SBOM、漏洞门禁、依赖校验与镜像扫描接进 CI，实现制品可追溯。

调优顺序（⚠️ 切忌上来就改参数）：

  1. 先量化：JFR 录制 + GC 日志确认「真的是 GC 问题」而非锁竞争/下游慢。

6.2.2 CPU 火焰图：从 JFR 采样到可读调用栈 ​

火焰图的本质是把采样栈按前缀聚合并横向铺开：宽度 = 样本占比，纵向 = 调用深度，颜色无语义。JFR 的 jdk.ExecutionSample 默认每 10ms 采样一次，8 秒约 600~800 个样本，足够定位「谁吃掉了 CPU」。

示例负载轮转四种热点函数，便于观察多个分支而不是一根柱子：

examples/profiling/src/main/kotlin/profiling/Workloads.kt:65-79可在线运行
kotlin
    fun cpu(seconds: Long) {
        val deadline = System.nanoTime() + seconds * 1_000_000_000L
        var checksum = 0L
        var rounds = 0L
        while (System.nanoTime() < deadline) {
            checksum = checksum xor when (rounds % 4) {
                0L -> cpuIteration()
                1L -> hashWork()
                2L -> matrixWork()
                else -> sortWork()
            }
            rounds++
        }
        println("workload=cpu rounds=$rounds checksum=$checksum")
    }

6.2.4 分配剖析：区分「分配速率」与「存活集」 ​

分配问题有两种，工具指标完全不同：

  • 分配速率高（短命对象多）→ 抬高 GC 频率，看 JFR jdk.ObjectAllocationSample 的 weight（估算字节数）。
  • 存活集大（对象被长期持有）→ 抬高老年代占用，看类直方图与 jdk.OldObjectSample。

实测（15 秒分配负载，8 秒录制，2390 个采样事件）：

排名类型估算分配量采样次数解读
1byte[]（[B）60405.7 MB23858KB 临时数组是分配主力
2StringBuilder3.7 MB1长字符串拼接，量小但单次大
3String0.0 MB2被 JIT 常量折叠

同一时刻 jcmd <pid> GC.class_histogram 显示 [B 仅 1.09 MB / 15561 个实例——说明 60GB 是累计分配速率，而不是驻留内存。把这两个数字混为一谈，就会得出「内存泄漏」的错误结论。

降级说明：JFR 的 weight 是抽样放大后的估算值，不能当计费用量；需要精确 TLAB 数据时用 async-profiler 的 -e alloc 或 JFR 的 jdk.ObjectAllocationOutsideTLAB。

6.2.8 与 D3 业务指标对照：先定位链路，再定位代码 ​

6.3.2 JankStats：线上帧卡顿的常态化监控 ​

Perfetto 是「事后深挖」，JankStats 是「线上常驻」：它以 Choreographer 的帧回调为数据源，逐帧记录 UI 线程与总耗时，超过刷新周期即标记 jank，并支持给帧打业务状态标签（如 screen=checkout）。

kotlin
// 文件: JankMonitor.kt —— 把 JankStats 接到页面生命周期，按页面聚合卡顿率
package com.example.guide.perf

import android.view.Window
import androidx.metrics.performance.JankStats
import androidx.metrics.performance.FrameData

class JankMonitor(private val window: Window, private val report: (String, Long) -> Unit) {
    private val stats: JankStats = JankStats.createAndTrack(
        window,
        object : JankStats.OnFrameListener {
            override fun onFrame(frameData: FrameData) {
                if (!frameData.isJank) return
                // frameDurationUiNanos 是这一帧的实际耗时，超过 16.6ms 即掉帧
                report("screen", frameData.frameDurationUiNanos)
            }
        },
    )

    /** 页面切换时打标签，便于按页面/场景聚合卡顿率 */
    fun setState(key: String, value: String) = stats.setState(key, value)

    fun stop() = stats.isTrackingEnabled = false
}

6.5 加解密与密钥管理 ​

密钥管理的铁律：密钥不落代码、不落配置文件、不落 Git。Android 用 Keystore，服务端用 KMS/Vault。

kotlin
// KeystoreCrypto.kt —— Keystore 内生成密钥并加密
package com.shop.security

import android.security.keystore.KeyGenParameterSpec
import android.security.keystore.KeyProperties
import java.security.KeyStore
import javax.crypto.Cipher
import javax.crypto.KeyGenerator
import javax.crypto.SecretKey
import javax.crypto.spec.GCMParameterSpec

object KeystoreCrypto {
    private const val ALIAS = "shop_token_key"

    private fun getOrCreateKey(): SecretKey {
        val ks = KeyStore.getInstance("AndroidKeyStore").apply { load(null) }
        (ks.getEntry(ALIAS, null) as? KeyStore.SecretKeyEntry)?.let { return it.secretKey }
        val spec = KeyGenParameterSpec.Builder(
            ALIAS, KeyProperties.PURPOSE_ENCRYPT or KeyProperties.PURPOSE_DECRYPT
        )
            .setBlockModes(KeyProperties.BLOCK_MODE_GCM)
            .setEncryptionPaddings(KeyProperties.ENCRYPTION_PADDING_NONE)
            .setUserAuthenticationRequired(false)         // 金融场景可要求生物识别
            .build()
        return KeyGenerator.getInstance(KeyProperties.KEY_ALGORITHM_AES, "AndroidKeyStore")
            .apply { init(spec) }.generateKey()           // 密钥只存在于 TEE/SE，导不出来
    }

    fun encrypt(plain: ByteArray): Pair<ByteArray, ByteArray> {
        val cipher = Cipher.getInstance("AES/GCM/NoPadding")
        cipher.init(Cipher.ENCRYPT_MODE, getOrCreateKey())
        return cipher.doFinal(plain) to cipher.iv         // (密文, IV) 分开存储
    }

    fun decrypt(cipherText: ByteArray, iv: ByteArray): ByteArray {
        val cipher = Cipher.getInstance("AES/GCM/NoPadding")
        cipher.init(Cipher.DECRYPT_MODE, getOrCreateKey(), GCMParameterSpec(128, iv))
        return cipher.doFinal(cipherText)
    }
}

6.5.2 存储安全边界 ​

存储安全不是「全部加密」，而是按数据分级做取舍：

数据建议说明
密码Argon2id / bcrypt不可逆；禁止明文与可逆加密
PII（手机号/身份证）字段级加密或令牌化展示脱敏；检索用独立哈希列
金额最小货币单位整数避免浮点误差，便于审计
日志脱敏 + 保留期禁止打印 token、完整卡号、身份证
备份加密 + 独立密钥备份泄露往往比主库泄露影响更大

判断顺序：是否必须存 → 存多久 → 最后才是怎么加密。很多泄露源于「本不该留的数据留了三年」。

6.7.1 服务端认证授权落地：接口级 scope ​

移动端解决「凭据怎么存」，服务端解决「谁能调哪个接口」。参考工程的做法是：

  1. 认证交给框架：JWT resource server 校验签名 / issuer / 过期，业务代码不碰 token 解析。
  2. 授权按「资源 + 动作」绑定 scope：SCOPE_orders:read / SCOPE_orders:write，写在 SecurityFilterChain。
  3. Controller 不写权限分支；新增接口必须显式声明权限，漏写即默认拒绝。
  4. 401 返回 WWW-Authenticate: Bearer，401/403 统一 application/problem+json。

package com.example.backend.security

import com.fasterxml.jackson.databind.ObjectMapper
import com.nimbusds.jose.jwk.source.ImmutableSecret
import org.springframework.beans.factory.annotation.Value
import org.springframework.context.annotation.Bean
import org.springframework.context.annotation.Configuration
import org.springframework.http.HttpMethod
import org.springframework.http.HttpStatus
import org.springframework.http.MediaType
import org.springframework.security.config.annotation.web.builders.HttpSecurity
import org.springframework.security.config.annotation.web.configuration.EnableWebSecurity
import org.springframework.security.config.http.SessionCreationPolicy
import org.springframework.security.oauth2.jose.jws.MacAlgorithm
import org.springframework.security.oauth2.jwt.JwtDecoder
import org.springframework.security.oauth2.jwt.JwtEncoder
import org.springframework.security.oauth2.jwt.JwtValidators
import org.springframework.security.oauth2.jwt.NimbusJwtDecoder
import org.springframework.security.oauth2.jwt.NimbusJwtEncoder
import org.springframework.security.web.SecurityFilterChain
import java.nio.charset.StandardCharsets
import javax.crypto.spec.SecretKeySpec

/**
 * 认证：JWT（HS256）resource server，密钥由环境变量/KMS 注入，适合离线可复现教学。
 * 授权：接口级 scope（orders:read / orders:write），不把权限判断散落在 Controller。
 *
 * 生产注意：HS256 只适合单服务内部；多服务/第三方接入应换 RS256/ES256 + JWKS，
 * 并开启密钥轮换（见 mastery-security-supply-chain.md）。
 */
@Configuration
@EnableWebSecurity
class SecurityConfig(private val objectMapper: ObjectMapper) {

    @Bean
    fun jwtDecoder(
        @Value("\${shop.security.jwt.secret}") secret: String,
        @Value("\${shop.security.jwt.issuer}") issuer: String,
    ): JwtDecoder {
        require(secret.length >= 32) { "HS256 密钥至少 32 字节，当前长度 ${secret.length}" }
        val key = SecretKeySpec(secret.toByteArray(StandardCharsets.UTF_8), "HmacSHA256")
        return NimbusJwtDecoder.withSecretKey(key)
            .macAlgorithm(MacAlgorithm.HS256)
            .build()
            .apply { setJwtValidator(JwtValidators.createDefaultWithIssuer(issuer)) }
    }

    @Bean
    fun jwtEncoder(@Value("\${shop.security.jwt.secret}") secret: String): JwtEncoder {
        val key = SecretKeySpec(secret.toByteArray(StandardCharsets.UTF_8), "HmacSHA256")
        return NimbusJwtEncoder(ImmutableSecret(key))
    }

    @Bean
    fun securityFilterChain(http: HttpSecurity, jwtDecoder: JwtDecoder): SecurityFilterChain =
        http
            .csrf { it.disable() }                                  // 无状态 API 不需要 CSRF token
            .sessionManagement { it.sessionCreationPolicy(SessionCreationPolicy.STATELESS) }
            .authorizeHttpRequests { auth ->
                auth.requestMatchers("/actuator/health/**", "/actuator/info").permitAll()
                auth.requestMatchers("/actuator/prometheus").permitAll()   // 仅内网抓取；公网应加网络策略
                auth.requestMatchers(HttpMethod.POST, "/api/auth/dev-token").permitAll()
                auth.requestMatchers(HttpMethod.GET, "/api/orders/**").hasAuthority("SCOPE_orders:read")
                auth.requestMatchers(HttpMethod.POST, "/api/orders/**").hasAuthority("SCOPE_orders:write")
                auth.anyRequest().authenticated()
            }
            .oauth2ResourceServer { oauth2 -> oauth2.jwt { it.decoder(jwtDecoder) } }
            .exceptionHandling { handling ->
                handling.authenticationEntryPoint { request, response, _ ->
                    writeProblem(response, HttpStatus.UNAUTHORIZED, "未认证", "缺少或无效的 Bearer Token", request.requestURI)
                }
                handling.accessDeniedHandler { request, response, _ ->
                    writeProblem(response, HttpStatus.FORBIDDEN, "无权限", "当前 Token 缺少所需 scope", request.requestURI)
                }
            }
            .build()

    private fun writeProblem(
        response: jakarta.servlet.http.HttpServletResponse,
        status: HttpStatus,
        title: String,
        detail: String,
        instance: String,
    ) {
        response.status = status.value()
        response.contentType = MediaType.APPLICATION_PROBLEM_JSON_VALUE
        if (status == HttpStatus.UNAUTHORIZED) {
            response.setHeader("WWW-Authenticate", "Bearer")
        }
        objectMapper.writeValue(
            response.outputStream,
            mapOf(
                "type" to "https://errors.shop/${status.value()}",
                "title" to title,
                "status" to status.value(),
                "detail" to detail,
                "instance" to instance,
            ),
        )
    }
}

// 文件: web/ApiExceptionHandler.kt —— 统一错误响应（RFC 7807 ProblemDetail）
package com.example.backend.web

import com.example.backend.order.OrderNotFoundException
import com.example.backend.order.OrderStateConflictException
import com.example.backend.outbox.OutboxNotFoundException
import com.example.backend.outbox.OutboxStateConflictException
import io.opentelemetry.api.trace.Span
import jakarta.servlet.http.HttpServletRequest
import jakarta.validation.ConstraintViolationException
import org.slf4j.LoggerFactory
import org.springframework.http.HttpStatus
import org.springframework.http.ProblemDetail
import org.springframework.http.converter.HttpMessageNotReadableException
import org.springframework.web.bind.MethodArgumentNotValidException
import org.springframework.web.bind.MissingRequestHeaderException
import org.springframework.web.bind.annotation.ExceptionHandler
import org.springframework.web.bind.annotation.RestControllerAdvice
import org.springframework.web.method.annotation.MethodArgumentTypeMismatchException
import java.net.URI

@RestControllerAdvice
class ApiExceptionHandler {

    private val log = LoggerFactory.getLogger(javaClass)

    @ExceptionHandler(OrderNotFoundException::class)
    fun handleNotFound(e: OrderNotFoundException, request: HttpServletRequest): ProblemDetail =
        problem(HttpStatus.NOT_FOUND, "订单不存在", e.message, "order-not-found", request)

    @ExceptionHandler(OrderStateConflictException::class)
    fun handleConflict(e: OrderStateConflictException, request: HttpServletRequest): ProblemDetail =
        problem(HttpStatus.CONFLICT, "订单状态冲突", e.message, "order-state-conflict", request)

    @ExceptionHandler(OutboxNotFoundException::class)
    fun handleOutboxNotFound(e: OutboxNotFoundException, request: HttpServletRequest): ProblemDetail =
        problem(HttpStatus.NOT_FOUND, "Outbox 记录不存在", e.message, "outbox-not-found", request)

    @ExceptionHandler(OutboxStateConflictException::class)
    fun handleOutboxConflict(e: OutboxStateConflictException, request: HttpServletRequest): ProblemDetail =
        problem(HttpStatus.CONFLICT, "Outbox 状态冲突", e.message, "outbox-state-conflict", request)

    @ExceptionHandler(MethodArgumentNotValidException::class)
    fun handleValidation(e: MethodArgumentNotValidException, request: HttpServletRequest): ProblemDetail {
        val errors = e.bindingResult.fieldErrors.map { "${it.field}: ${it.defaultMessage}" }
        return problem(HttpStatus.BAD_REQUEST, "请求参数不合法", "请检查请求体字段", "validation-failed", request)
            .apply { setProperty("errors", errors) }
    }

    @ExceptionHandler(ConstraintViolationException::class)
    fun handleConstraint(e: ConstraintViolationException, request: HttpServletRequest): ProblemDetail =
        problem(HttpStatus.BAD_REQUEST, "请求参数不合法", e.constraintViolations.joinToString("; ") { it.message }, "validation-failed", request)

    @ExceptionHandler(MissingRequestHeaderException::class)
    fun handleMissingHeader(e: MissingRequestHeaderException, request: HttpServletRequest): ProblemDetail =
        problem(HttpStatus.BAD_REQUEST, "缺少请求头", "缺少必需请求头：${e.headerName}", "missing-header", request)

    @ExceptionHandler(MethodArgumentTypeMismatchException::class)
    fun handleTypeMismatch(e: MethodArgumentTypeMismatchException, request: HttpServletRequest): ProblemDetail =
        problem(HttpStatus.BAD_REQUEST, "参数类型不匹配", "参数 ${e.name} 取值非法", "type-mismatch", request)

    @ExceptionHandler(HttpMessageNotReadableException::class)
    fun handleUnreadable(e: HttpMessageNotReadableException, request: HttpServletRequest): ProblemDetail =
        problem(HttpStatus.BAD_REQUEST, "请求体无法解析", "请求体不是合法 JSON 或字段类型错误", "malformed-body", request)

    // 兜底：不把堆栈/SQL 细节暴露给调用方，只在服务端日志保留
    @ExceptionHandler(Exception::class)
    fun handleUnexpected(e: Exception, request: HttpServletRequest): ProblemDetail {
        log.error("未处理异常 uri={}", request.requestURI, e)
        return problem(HttpStatus.INTERNAL_SERVER_ERROR, "服务器内部错误", "请携带 traceId 联系运维", "internal-error", request)
    }

    private fun problem(
        status: HttpStatus,
        title: String,
        detail: String?,
        type: String,
        request: HttpServletRequest,
    ): ProblemDetail =
        ProblemDetail.forStatusAndDetail(status, detail ?: title).apply {
            this.title = title
            this.type = URI.create("https://errors.shop/$type")
            this.instance = URI.create(request.requestURI)
            setProperty("traceId", Span.current().spanContext.traceId)
        }
}

企业级场景分析 ​

场景一：金融类 App 合规整改 ​

某银行 App 接受监管渗透测试后收到 23 项整改，典型项：日志打印身份证后 6 位（M10）、抓包可改转账金额（M3）、Root 设备可运行（M7）。整改组合：release 构建用 R8 移除 Log.d/v（-assumenosideeffects）、全链路证书固定 + 请求签名（HMAC-SHA256 防篡改）、接入 SafetyNet/Play Integrity 并做服务端校验而非仅本地判断（本地检测可被 hook）。经验：所有「客户端校验」都必须假设可被绕过，最终校验在服务端。

场景二：交易撮合服务的 ZGC 迁移 ​

某券商撮合服务（堆 32G）用 G1 时 Full GC 偶发 800ms 停顿，盘中触发风控告警。迁移 JDK 21 分代 ZGC 后停顿稳定在 0.5ms 内，吞吐损失约 5%，通过扩容 1 个实例对冲。经验：延迟敏感服务先评估 ZGC/Shenandoah；调参救不了大堆 G1 的 Full GC，换收集器才是正解。

场景三：LeakCanary 治理专项 ​

某 App 用户画像显示低端机 OOM 率 0.8%。团队发起「泄漏清零」专项：CI 上跑 Monkey + LeakCanary（leakcanary-android-instrumentation），泄漏即失败；两周修复 41 处（Top3：静态 View 引用、未注销的广播、匿名内部类 Handler），OOM 率降至 0.15%，商店评分 +0.2。

实践任务 ​

  1. ★ 给一个 Spring Boot 服务加 G1 GC 日志参数，压测 1 分钟后用日志分析工具（或肉眼）统计 Young GC 次数与平均停顿。
  2. ★★ 在 Android demo 中故意制造一个单例持有 Activity 的泄漏，用 LeakCanary 捕获并截图引用链，再修复它。
  3. ★★ 编写 R8 keep 规则保护一个 Gson 数据类与一个 JNI 类，打 release 包验证功能与混淆效果（jadx 查看）。
  4. ★★★ 用 Keystore 实现 Token 的加密存储与读取，卸载重装后验证旧密文不可解（并说明工程上如何应对）。
  5. ★★★ 为 OkHttp 配置证书固定（含备份 pin），用 Charles 抓包验证失败，再用 debug 变体放行抓包。

小结与自测 ​

要点回顾：GC 先诊断后调参，大堆低延迟选 ZGC；Android 启动靠 Baseline Profile + 初始化收敛；泄漏治理靠 LeakCanary + CI 门禁；keep 规则随发版归档 mapping；密钥不出 Keystore/KMS；客户端校验永远可被绕过。服务端侧用接口级 scope 做授权、统一 problem+json 错误契约、KMS 注入与 kid 双密钥轮换，并明确传输/存储边界；供应链侧用 SBOM + OSV 阻断 HIGH/CRITICAL、verification-metadata.xml 校验和与镜像扫描，让制品可追溯。

自测题：

  1. 什么特征的服务应该选 ZGC 而不是 G1？
  2. 为什么证书固定必须配置备份 pin？
  3. AES/GCM 加密时 IV 能否硬编码？为什么？
  4. isMinifyEnabled=true 与 isShrinkResources=true 的区别？
  5. 为什么 Root 检测不能只放在客户端做？
  6. 为什么 OSV querybatch 不能单独用于门禁？SBOM 为什么要限定 runtimeClasspath？
参考答案（点击展开）
  1. 堆 ≥16G 或停顿要求 <10ms 的延迟敏感服务；ZGC 停顿与堆大小无关，稳定在亚毫秒级。
  2. 主证书到期或 CA 更换时，没有备份 pin 会导致所有已发布 App 无法联网，属于可用性事故。
  3. 不能。GCM 模式下同一密钥重复使用 IV 会导致密钥流复用，攻击者可恢复明文甚至伪造密文；IV 必须每次随机生成并随密文存储。
  4. 前者做代码层面的混淆/压缩/裁剪；后者移除代码中未被引用的资源文件，需前者开启才生效。
  5. 客户端环境不可信，本地检测结果可被 Xposed/Frida 篡改；必须由服务端结合 Play Integrity 等服务端判定结果做最终决策。
  6. querybatch 只返回漏洞 id，严重度需要再拉 /v1/vulns/{id}，否则全部 UNKNOWN 导致 HIGH/CRITICAL 漏阻断；SBOM 限定 runtimeClasspath 是为了让门禁针对真实发布产物，避免 test-only 依赖制造无关告警。
