D9 · KMP 与 Compose Multiplatform ​

第二部「精通专题」第九篇。目标：把领域逻辑、序列化、网络边界抽到共享模块， 用 Compose Multiplatform 让同一套 UI 跑在 Android 与桌面；iOS 明确边界与补齐步骤，不假装已验证。 示例工程：examples/kmp-app。

D9.0 谁该读，解决什么问题 ​

读者典型痛点读完能做什么
跨端负责人「共享到什么程度」吵不清用「领域/序列化/网络/UI」四层边界做决策
Android 工程师一上 KMP 就全平台崩用 expect/actual 把差异收敛到边界
iOS 工程师Kotlin 代码怎么进 Xcode 不清楚知道 framework 产物与 embed 步骤
架构师共享 UI 值不值用成本/收益表做取舍，而不是跟风

前置知识：第 5 章（尤其 5.5 Hilt vs Koin）、 D4 多模块与变体、第 3 章 Version Catalog。

D9.1 先做战略判断：共享什么，不共享什么 ​

5.5 节 的矩阵里已经给出一个信号： KMP 跨端项目更适合 Koin（运行时装配、无代码生成，共享模块不必为每个平台生成 DI 代码）。 把这句话展开，就是 KMP 的分层策略：

mermaid
flowchart TD
    UI[Compose UI<br/>可选共享] --> VM[ViewModel / 状态机<br/>可共享]
    VM --> Domain[领域模型 + 校验 + 序列化<br/>强烈建议共享]
    Domain --> Net[网络边界 HttpTextClient / Ktor<br/>共享接口，实现分平台]
    Net --> Platform[平台能力 expect/actual<br/>文件/时间/日志/加密]

层建议理由
领域模型与规则共享三端同一套校验，避免「Android 能取消、iOS 不能」
序列化契约共享字段名、默认值、未知字段策略必须一致
网络接口与 DTO共享接口稳定，底层换 OkHttp/Ktor/Darwin 不影响业务
状态与用例视团队共享能减少重复，但调试成本上升
UI谨慎共享Compose MP 已可用于 Android/Desktop/iOS，但 iOS 体验与原生控件差异要评估
平台深度能力不共享推送、生物识别、后台任务用 expect/actual 或原生

✅ 判断口诀：「业务规则会不会三端漂移？」会 → 共享；「平台体验是否必须原生？」是 → 不共享。

package com.example.kmp.shared

import kotlinx.serialization.Serializable

@Serializable
data class Order(
    val id: Long,
    val customerId: String,
    val itemName: String,
    val amountCents: Long,
    val status: String,
    val version: Long = 0,
)

@Serializable
data class OrderPage(
    val items: List<Order>,
    val page: Int,
    val size: Int,
    val total: Long,
)

/** 领域规则放在 commonMain：Android / iOS / JVM 共用同一套校验，避免三端漂移。 */
fun Order.isCancellable(): Boolean = status == "CREATED"

fun Order.displayAmount(): String {
    val whole = amountCents / 100
    val cents = (amountCents % 100).toString().padStart(2, '0')
    return "¥$whole.$cents"
}

// 文件: shared/src/commonMain/kotlin/com/example/kmp/shared/OrderCodec.kt
package com.example.kmp.shared

import kotlinx.serialization.json.Json

/** 序列化也是共享层的一部分：字段名、默认值、未知字段策略三端一致。 */
object OrderCodec {
    private val json = Json {
        ignoreUnknownKeys = true   // 服务端新增字段不破坏旧客户端
        encodeDefaults = true
        prettyPrint = false
    }

    fun encode(order: Order): String = json.encodeToString(Order.serializer(), order)

    fun decode(text: String): Order = json.decodeFromString(Order.serializer(), text)

    fun decodePage(text: String): OrderPage = json.decodeFromString(OrderPage.serializer(), text)
}

三条纪律：

  1. 规则跟着模型走：isCancellable() / displayAmount() 放 commonMain，三端不再各写一份。 注意格式化不能用 JVM 专属的 "%.2f".format，这里用纯字符串实现，才能在 iOS 编译通过。
  2. 未知字段要容忍：ignoreUnknownKeys = true，服务端新增字段不会让旧客户端崩溃。
  3. 默认值要显式编码：encodeDefaults = true，避免「省略字段」被下游误判为未传。

⚠️ 契约演进：新增字段给默认值；删除字段先保留一版；改语义要升 event/schema 版本。 这与 D11 事件 payload 的演进规则相同。

package com.example.kmp.shared

import kotlinx.coroutines.CoroutineDispatcher
import kotlinx.coroutines.withContext

/**
 * 网络边界：只做「URL → 文本 → 领域模型」，超时/重试/鉴权头由实现层负责。
 * 生产建议换成 Ktor Client（Android: OkHttp，iOS: Darwin），接口保持不变。
 */
class OrderApi(
    private val client: HttpTextClient = createHttpTextClient(),
    private val baseUrl: String = "https://api.example.com",
) {
    suspend fun page(page: Int, size: Int, dispatcher: CoroutineDispatcher? = null): OrderPage {
        val call: suspend () -> String = {
            client.get("$baseUrl/api/orders?page=$page&size=$size")
        }
        val text = if (dispatcher == null) call() else withContext(dispatcher) { call() }
        return OrderCodec.decodePage(text)
    }
}

/** 演示/测试用：不访问网络的仓储实现，Compose 页面默认用它。 */
class InMemoryOrderRepository {
    private val orders = mutableListOf(

        Order(2, "cust-2", "Gradle 构建", 4900, "CANCELLED"),
        Order(3, "cust-3", "协程深水区", 9900, "CREATED"),
    )

    suspend fun load(): List<Order> = orders.toList()
}

JVM 与 Android 的实现相同（HttpURLConnection + Dispatchers.IO），iOS 用 NSURLSession：

examples/kmp-app/shared/src/jvmMain/kotlin/com/example/kmp/shared/Platform.jvm.kt
kotlin
// 文件: shared/src/jvmMain/kotlin/com/example/kmp/shared/Platform.jvm.kt
package com.example.kmp.shared

import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.withContext
import java.net.HttpURLConnection
import java.net.URI

actual fun platformName(): String = "JVM ${System.getProperty("java.version")}"

actual fun createHttpTextClient(): HttpTextClient = object : HttpTextClient {
    override suspend fun get(url: String): String = withContext(Dispatchers.IO) {
        val connection = URI(url).toURL().openConnection() as HttpURLConnection
        try {
            connection.requestMethod = "GET"
            connection.connectTimeout = 5_000
            connection.readTimeout = 5_000
            connection.setRequestProperty("Accept", "application/json")
            val code = connection.responseCode
            if (code !in 200..299) error("HTTP $code")
            connection.inputStream.bufferedReader().use { it.readText() }
        } finally {
            connection.disconnect()
        }
    }
}

// 文件: shared/src/iosMain/kotlin/com/example/kmp/shared/Platform.ios.kt
package com.example.kmp.shared

import kotlinx.cinterop.ExperimentalForeignApi
import kotlinx.cinterop.addressOf
import kotlinx.cinterop.usePinned
import kotlinx.coroutines.suspendCancellableCoroutine
import platform.Foundation.NSData
import platform.Foundation.NSError
import platform.Foundation.NSHTTPURLResponse
import platform.Foundation.NSURL
import platform.Foundation.NSURLRequest
import platform.Foundation.NSURLSession
import platform.Foundation.dataTaskWithRequest
import platform.posix.memcpy
import kotlin.coroutines.resume
import kotlin.coroutines.resumeWithException

actual fun platformName(): String = "iOS"

@OptIn(ExperimentalForeignApi::class)
actual fun createHttpTextClient(): HttpTextClient = object : HttpTextClient {
    override suspend fun get(url: String): String = suspendCancellableCoroutine { cont ->
        val request = NSURLRequest.requestWithURL(NSURL.URLWithString(url)!!)
        val task = NSURLSession.sharedSession.dataTaskWithRequest(request) { data, response, error ->
            when {
                error != null -> cont.resumeWithException(IllegalStateException(error.localizedDescription))
                else -> {
                    val status = (response as? NSHTTPURLResponse)?.statusCode ?: 200L
                    if (status !in 200L..299L) {
                        cont.resumeWithException(IllegalStateException("HTTP $status"))
                    } else {
                        cont.resume(data?.let(::bytesToString) ?: "")
                    }
                }
            }
        }
        cont.invokeOnCancellation { task.cancel() }
        task.resume()
    }
}

@OptIn(ExperimentalForeignApi::class)
private fun bytesToString(data: NSData): String {
    val bytes = data.bytes ?: return ""
    val length = data.length.toInt()
    val array = ByteArray(length)
    array.usePinned { pinned ->
        memcpy(pinned.addressOf(0), bytes, length.toULong())
    }
    return array.decodeToString()
}

                LazyColumn(verticalArrangement = Arrangement.spacedBy(8.dp)) {
                    items(orders) { order -> OrderCard(order) }
                }
            }
        }
    }
}

@Composable
private fun OrderCard(order: Order) {
    Card(modifier = Modifier.fillMaxWidth()) {
        Row(modifier = Modifier.fillMaxWidth().padding(12.dp)) {
            Column(modifier = Modifier.weight(1f)) {
                Text(order.itemName, style = MaterialTheme.typography.titleMedium)
                Text("客户 ${order.customerId} · ${order.status}", style = MaterialTheme.typography.bodySmall)
            }
            Column {
                Text(order.displayAmount(), style = MaterialTheme.typography.titleMedium)
                if (order.isCancellable()) {
                    Text("可取消", style = MaterialTheme.typography.bodySmall)
                }
            }
        }
    }
}

D9.6 iOS 补齐步骤（已编译共享层，未跑 App） ​

已验证：iosSimulatorArm64 的 shared klib 编译通过（第一次需下载 Kotlin/Native，本机用 KONAN_DATA_DIR=/tmp/konan 隔离工具链目录）。

未验证：iOS App 链接、模拟器启动、真机签名。原因是： ① 本示例未创建 Xcode 工程； ② Kotlin/Native 2.0.21 官方支持的 Xcode 版本低于本机 Xcode 27.2，framework 链接可能需升级 Kotlin 或降级 Xcode； ③ GitHub/Docker 网络受限不代表 iOS 工具链可用，不能拿 klib 编译冒充 App 跑通。

补齐步骤（按顺序）：

  1. 升级 Kotlin：把 kotlin 升到与 Xcode 27 兼容的版本（K2/Native 新版本），并同步 libs.versions.toml。
  2. 开启 iOS 目标：./gradlew -PwithIos=true :shared:linkDebugFrameworkIosSimulatorArm64，产出 shared/build/bin/iosSimulatorArm64/debugFramework/Shared.framework。
  3. 创建 Xcode 工程 iosApp/：SwiftUI App + ContentView，在 Build Phases 加 Run Script：
    bash
    cd "$SRCROOT/.."
./gradlew :shared:embedAndSignAppleFrameworkForXcode
    1
    2
    并把 framework 的搜索路径指向 shared/build/xcode-frameworks/$(CONFIGURATION)/$(SDK_NAME)。
  4. 在 Swift 调 Kotlin：import Shared；Kotlin 的 suspend 函数在 Swift 里是 completionHandler 形式， 或用 kotlinx-coroutines-core 的 MainScope 封装。
  5. Compose UI 上 iOS（可选）：在 composeApp 加 iOS 目标，用 ComposeUIViewController { App() } 在 SwiftUI 里以 UIViewControllerRepresentable 承载；这一步建议在共享 UI 稳定后再做。
  6. CI：iOS 必须在 macOS runner 上跑，Xcode 版本与 Kotlin 版本一起锁；不满足就显式跳过并标注。

⚠️ 顺序不能反：先让 linkDebugFramework 通过，再谈 Xcode 工程；否则会把「Swift 配置问题」误判成「KMP 不可用」。

D9.8 企业级取舍与坑 ​

坑现象修法
默认开启 iOS 目标无 Kotlin/Native 的机器全部构建失败用 -PwithIos 开关，CI 分 job
JVM 专属 API 混进 commonMainiOS 编译报 Unresolved referencecommonMain 只用 stdlib + kotlinx；格式化/时间自己实现或 kotlinx-datetime
Compose 版本与 Kotlin 不匹配编译器插件报错用 org.jetbrains.kotlin.plugin.compose，版本跟随 Kotlin
Android 资源/Manifest 缺失assembleDebug 失败composeApp 必须有 AndroidManifest.xml 与 namespace
依赖膨胀共享层引入 Ktor/OkHttp 导致 iOS 链接失败依赖分层：接口在 common，实现在平台
调试困难崩溃栈只有 Kotlin 符号保留符号表；Android 上传 mapping，iOS 用 dSYM

该不该共享 UI？

场景建议
内部工具、原型、双端高度一致共享 Compose UI，收益最大
双端体验要求原生（导航、动效、控件）只共享领域/网络，UI 各写
iOS 团队独立演进共享业务，不共享 UI
需要尽快上线 iOS先共享逻辑，UI 后置

D9.9 排障路径 ​

现象先查根因处置
Unresolved reference: java.*commonMain 是否 import JVM 包JVM API 泄漏下沉到 jvmMain 或换 multiplatform 库
iOS 编译卡在下载网络与 KONAN_DATA_DIRKotlin/Native 未缓存预置工具链或 CI 缓存 .konan
assembleDebug 找不到 SDKANDROID_HOME / local.propertiesSDK 未配置设环境变量或写 sdk.dir
framework 链接报 Xcode 版本linkDebugFramework 日志Kotlin 与 Xcode 不兼容升级 Kotlin 或锁 Xcode
序列化字段对不上服务端 JSON 与 DTO缺默认值/字段改名加默认值 + ignoreUnknownKeys + 契约测试
桌面能跑、Android 崩Logcat 栈AndroidManifest/主题/权限先看 Manifest 与 minSdk

D9.10 实践任务 ​

  1. ★ 把 InMemoryOrderRepository 换成 OrderApi，让桌面 App 真正请求后端（可用 backend-service）。
  2. ★★ 增加一个 expect fun formatDateTime(...)：JVM 用 java.time，iOS 用 NSDateFormatter，并在 commonTest 校验格式。
  3. ★★ 把 HttpTextClient 换成 Ktor Client，Android 用 OkHttp 引擎，iOS 用 Darwin 引擎，接口保持不变。
  4. ★★★ 按 D9.6 走通 iOS：linkDebugFramework → Xcode 工程 → 模拟器启动 App()。
  5. ★★★ 给共享层加二进制兼容检查（apiValidation 或 Kotlin BCV），防止改字段破坏已发布 SDK。

小结与自测 ​

要点回顾：KMP 的核心不是「共享一切」，而是把会漂移的业务规则共享，把平台差异收敛到 expect/actual； Compose Multiplatform 可以先在 Android + Desktop 验证，iOS 需要单独的 Xcode 工程与工具链验证； 没有验证过的平台，必须在文档里写明。

自测题：

  1. 为什么 displayAmount() 不能用 "%.2f".format？
  2. expect/actual 与「接口 + 平台注入」各适合什么场景？
  3. 为什么 iOS 目标默认关闭，而不是默认开启？
  4. 共享 UI 的收益与代价分别是什么？
  5. 只编译出 shared.klib 能说明 iOS App 可运行吗？
参考答案（点击展开）
  1. String.format 是 JVM 专属 API，commonMain 要在 iOS 编译，必须用纯 Kotlin 实现或多平台库。
  2. expect/actual 适合「每个平台必须提供、无状态」的能力（平台名、时间格式）；接口注入适合需要替换实现、便于测试的网络/存储边界。
  3. 声明 iOS 目标会让构建依赖 Kotlin/Native 工具链，无工具链的机器/CI 会直接失败；用属性开关按需启用。
  4. 收益：一套 UI、双端一致、迭代快；代价：平台控件/体验差异、调试与版本兼容成本、iOS 团队学习曲线。
  5. 不能。klib 只是 Kotlin 编译产物；还需要 framework 链接、Xcode 工程、签名与模拟器运行，任何一步都可能失败。
